### Введение

******

Плагин OpenCV (OpenCV Plugin) предоставляет нативную среду выполнения OpenCV 4.8.0, на которой построена обработка изображений в AutoJs6. API для работы с изображениями, такие как поиск изображений, поиск цвета и сопоставление с шаблоном, выполняют вычисления средствами OpenCV; после установки плагина хост AutoJs6 с поддержкой подключаемого OpenCV может пользоваться этими функциями как обычно, без какой-либо дополнительной настройки в скриптах.

Плагин построен на разделении обязанностей с приоритетом совместимости: хост AutoJs6 сохраняет OpenCV Java API, который напрямую вызывают скрипты, а плагин содержит точно соответствующую ему нативную библиотеку `libopencv_java4.so`. Благодаря этому установочный пакет хоста остается компактным, устройство устанавливает только плагин, соответствующий архитектуре его процессора (ABI), а среду выполнения OpenCV можно обновлять независимо от хоста.

******

### Основные возможности

******

- Работает сразу после установки: настройка не требуется; AutoJs6 автоматически обнаруживает плагин и по мере необходимости загружает среду выполнения OpenCV при запуске скриптов, работающих с изображениями.
- Пять вариантов APK: четыре пакета для одной ABI (`arm64-v8a`, `armeabi-v7a`, `x86`, `x86_64`) и универсальный пакет `universal`, поэтому каждое устройство устанавливает только необходимое.
- Сборка из официальных исходников: нативные библиотеки пересобраны из неизмененного дерева исходного кода OpenCV 4.8.0 (NDK r26b, API 24), а входные данные сборки и хеши для каждой ABI записаны в манифест provenance, что позволяет независимо воспроизвести и сверить результат.
- Проверка перед загрузкой: хост проверяет подпись плагина, версию OpenCV, версию контракта и отпечаток Java API, отвергая несоответствующие или подделанные среды выполнения.
- Одна среда выполнения C++ на процесс: плагин не дублирует `libc++_shared.so`, а использует общую для процесса зависимость, предоставляемую хостом, что предотвращает сбои из-за сосуществования нескольких сред выполнения C++.
- Прозрачное лицензирование: каждый APK содержит полные тексты лицензий OpenCV и статически связанных сторонних компонентов, а сводка приведена в THIRD_PARTY_NOTICES.md.
- Многоязычность: сведения о плагине, инструкции, README и changelog доступны на 10 языках.

### Как пользоваться

******

1. Скачайте со страницы [Releases](https://github.com/SuperMonster003/AutoJs6-Plugin-OpenCV/releases) APK плагина, подходящий для устройства, и установите его на устройство с AutoJs6; если сомневаетесь, выберите пакет `universal` или загляните в раздел `Как выбрать APK` ниже.
2. Откройте центр плагинов AutoJs6 и убедитесь, что плагин `OpenCV` распознан и включен.
3. Пишите и запускайте скрипты как обычно: когда скрипт обращается к API для работы с изображениями, AutoJs6 автоматически загружает нативную библиотеку OpenCV из плагина; код скриптов менять не нужно.
4. После обновления или переустановки плагина полностью выйдите из AutoJs6 и запустите его заново, прежде чем снова выполнять скрипты с изображениями, чтобы новая нативная библиотека вступила в силу.

> Если плагин не появился в центре плагинов, сначала обновите AutoJs6 до свежей версии (внутренняя сборка 5237 или новее). Сам плагин поддерживает устройства с Android 7.0 (API 24) и выше.

### Как выбрать APK

******

Каждый выпуск включает 5 APK, которые различаются только набором архитектур встроенных нативных библиотек:

| Пакет | Кому подходит |
|---|---|
| `arm64-v8a` | Подавляющее большинство современных телефонов и планшетов Android (64-битный ARM); выбирайте в первую очередь |
| `armeabi-v7a` | Более старые 32-битные устройства ARM |
| `x86_64` | 64-битные эмуляторы x86 и немногочисленные устройства x86 |
| `x86` | 32-битные эмуляторы x86 и немногочисленные устройства x86 |
| `universal` | Содержит все 4 архитектуры и имеет наибольший размер; работает на любом устройстве и остается надежным выбором, если вы не уверены |

Устанавливайте плагин `universal`, если APK Builder в AutoJs6 должен собирать приложения для нескольких архитектур: плагин для одной ABI может предоставить OpenCV только для своей архитектуры. Если по ошибке установлен пакет для одной ABI, не соответствующий устройству, плагин не сможет предоставить пригодную нативную библиотеку; переход на пакет `universal` решает проблему.

### Быстрая самопроверка

******

Убедитесь, что OpenCV включен в центре плагинов AutoJs6, перезапустите AutoJs6 и выполните этот скрипт. `images.initOpenCvIfNeeded()` действительно запускает обнаружение плагина, проверки совместимости и загрузку нативной библиотеки, а не только читает метаданные:

```javascript
images.initOpenCvIfNeeded();

const Build = android.os.Build;
const Process = android.os.Process;
const Core = org.opencv.core.Core;
const processAbis = Process.is64Bit()
    ? Build.SUPPORTED_64_BIT_ABIS
    : Build.SUPPORTED_32_BIT_ABIS;
const processAbi = processAbis.length > 0 ? processAbis[0] : "unknown";

console.log("OpenCV version: " + Core.getVersionString());
console.log("Process ABI: " + processAbi);
```

При успехе выводятся `OpenCV version: 4.8.0` и ABI процесса, например `arm64-v8a`. Если загрузка не удалась, проверяйте по порядку: установите пакет `universal`, обновите AutoJs6 до внутренней сборки 5237 или новее, затем полностью закройте и перезапустите AutoJs6.

### Частые вопросы

******

#### Как убедиться, что плагин работает?

Откройте центр плагинов AutoJs6: если плагин `OpenCV` виден в списке, хост его распознал. Затем запустите любой скрипт, использующий API для работы с изображениями; если результаты возвращаются нормально, нативная библиотека загружена успешно.

#### Почему в списке приложений нет значка плагина?

Так и задумано. У плагина нет отдельного интерфейса, и он не создает значок запуска; после установки его обнаруживает и использует сам AutoJs6 в фоновом режиме, а все взаимодействие происходит внутри AutoJs6.

#### После обновления плагина функции работы с изображениями работают неправильно или, кажется, все еще действует старая версия?

Загруженная нативная библиотека существует столько же, сколько процесс хоста, поэтому обновление плагина не подменяет библиотеку, которая уже используется. Полностью выйдите из AutoJs6 и запустите его заново, и новая нативная библиотека вступит в силу.

#### Что делать, если сообщается, что хост устарел или несовместим?

Плагину требуется внутренняя сборка AutoJs6 не ниже 5237, поэтому сначала обновите AutoJs6. Перед загрузкой хост проверяет версию контракта и отпечаток Java API и при любом несоответствии отказывается от загрузки, вместо того, чтобы работать со скрытыми рисками.

#### Плагин установлен, но функции работы с изображениями все равно не работают. В чем может быть причина?

Чаще всего причина в том, что APK не соответствует архитектуре устройства: пакет для одной ABI работает только на своей архитектуре. Установите пакет `universal`, чтобы исключить этот фактор; если не помогло, убедитесь, что версия AutoJs6 отвечает требованию, и повторите попытку после перезапуска AutoJs6.

#### Обращается ли плагин к сети и запрашивает ли чувствительные разрешения?

Нет. В его манифесте нет разрешений на сеть, хранилище, камеру и других чувствительных системных разрешений; объявлено только разрешение плагина, используемое для связи с AutoJs6. Его единственная задача состоит в передаче нативной библиотеки OpenCV хосту.

#### Почему OpenCV 4.8.0, а не более новая версия?

Нативная библиотека должна строго соответствовать OpenCV Java API, сохраненному в хосте (это проверяется по отпечатку SHA-256), поэтому версия OpenCV зафиксирована контрактом между хостом и плагином. Более новые версии OpenCV появятся в виде новых вариантов, когда их поддержит хост; за ходом работ можно следить в [ROADMAP.md](https://github.com/SuperMonster003/AutoJs6-Plugin-OpenCV/blob/master/ROADMAP.md).

### Разрешения и безопасность

******

Нативный код выполняется в одном процессе с хостом, поэтому от сборки до загрузки действует несколько уровней защиты:

- Проверяемое происхождение: нативные библиотеки пересобраны из зафиксированного коммита официального дерева исходников OpenCV, версии инструментов и хеши для каждой ABI записаны в `libs/opencv-native-4.8.0.provenance.json`; любой может воспроизвести сборку и сверить результат по инструкции [NATIVE_BUILD.md](https://github.com/SuperMonster003/AutoJs6-Plugin-OpenCV/blob/master/NATIVE_BUILD.md).
- Контроль при сборке: каждая сборка проверяет состав нативных библиотек, архитектуры ELF, хеши полезной нагрузки, отпечаток Java API, дублирующиеся классы OpenCV Java и файлы лицензий; публикуемые сборки дополнительно требуют доверенный идентификатор подписи.
- Проверка перед загрузкой: хост поочередно проверяет подпись плагина, версию OpenCV, версию контракта и SHA-256 Java API и при любом несоответствии отказывается от загрузки.
- Общую для процесса среду выполнения C++ предоставляет и предварительно загружает хост; плагин не содержит `libc++_shared.so`, что исключает сбои на границах несовместимых сред выполнения.
- Минимальные привилегии: без сетевых и чувствительных системных разрешений, без отдельного интерфейса, связь с хостом только через разрешение плагина AutoJs6.

Устанавливайте плагин только с официальной страницы [Releases](https://github.com/SuperMonster003/AutoJs6-Plugin-OpenCV/releases) или из других доверенных источников. Официальные пакеты используют идентификатор подписи, распознаваемый хостом; пакеты неизвестного происхождения могут не пройти проверку хоста или скрывать риски, даже если номер версии выглядит одинаково.

### Интерфейс плагина

******

Следующая информация предназначена для разработчиков хоста AutoJs6 и плагинов; по этим идентификаторам хост обнаруживает плагин и согласует совместимость:

```text
application id: io.github.supermonster003.autojs6.plugin.opencv
plugin id: opencv
engine: opencv
variant: 4.8.0
contract version: 2
minimum host build: 5237
native library: libopencv_java4.so
native ndk version: 26.1.10909125
java api sha-256: 340976552fda3cce525021f0b072427cabf0aa1c786fb80cfc4a3a8105d90b3f
```

Одна служба `OpenCvPluginInfoService` отвечает на действия `org.autojs.plugin.INFO` и `org.autojs.plugin.OPENCV`, оба с категорией `opencv-runtime`; интерфейс Binder представлен `IPluginInfoProvider` из common-plugin-api.

`PluginInfo.supportedAbis` вычисляется динамически по записям нативной библиотеки OpenCV, фактически присутствующим в установленном APK: пакет для одной ABI сообщает только свою архитектуру, а пакет `universal` сообщает все 4.

### Сборка и проверка

******

Этот раздел предназначен для разработчиков, которые хотят собрать плагин из исходного кода.

Сборка debug APK:

```powershell
.\gradlew.bat :app:assembleDebug
```

Запустите модульные тесты и проверьте целостность debug и release APK:

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:verifyOpenCvApks
```

Перед публикацией настройте доверенный идентификатор подписи в игнорируемом Git файле `sign.properties` и запустите:

```powershell
.\gradlew.bat :app:verifyOpenCvPublishableApks
```

Создайте пять подписанных APK, манифест SHA-256 и описание GitHub Release (полный процесс приведен в [RELEASING.md](https://github.com/SuperMonster003/AutoJs6-Plugin-OpenCV/blob/master/RELEASING.md)):

```bat
scripts\release\prepare-release.bat
```

Без `sign.properties` полезную нагрузку по-прежнему можно собрать и проверить, но созданные release APK не подписаны и не должны публиковаться.

Обычные сборки используют предсобранный нативный AAR из репозитория, поэтому локальная компиляция OpenCV не нужна; чтобы полностью пересобрать библиотеки из официальных исходников и сверить provenance, см. [NATIVE_BUILD.md](https://github.com/SuperMonster003/AutoJs6-Plugin-OpenCV/blob/master/NATIVE_BUILD.md).

### Локализация и генерация документов

******

```text
.readme/common.json
.readme/lang_*.json
.readme/template_readme.md
.changelog/lang_*.json
.changelog/template_changelog.md
.python/generate_markdown.py
app/src/main/assets/doc/CHANGELOG-*.md
app/src/main/res/values-*/strings.xml
app/src/main/res/raw-*/plugin_instruction.md
```

`strings.xml` содержит локализованное описание плагина, а `plugin_instruction.md` содержит инструкции, отображаемые хостом. README и changelog всегда правятся через JSON-источники в `.readme/` и `.changelog/` с последующим запуском `py .python/generate_markdown.py`; сгенерированные файлы вручную не редактируются. Команда `py .python/generate_markdown.py --check` проверяет синхронность источников и сгенерированных файлов.
